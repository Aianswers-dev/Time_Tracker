## Decisions made during the build

These go beyond or change the original docs; the docs are updated to match.

- **Deploy from GitHub Actions** (`.github/workflows/deploy.yml`) so the owner
  never needs a computer. It finds or creates the D1 database, applies
  migrations before deploying, and sets `AUTH_TOKEN` from `APP_TOKEN`.
- **VAPID keys are generated by the Worker** on first use and stored in D1
  (`server_config`); the subject is the app's own `https://` origin. Env
  secrets still override. The app password is the only secret the owner picks.
- **Sync**: one outbox op per user action; the server keeps the client's
  `updatedAt` and has its own `synced_at` cursor; snapshot reads overlap
  10 s; any refused op triggers a full resync, guarded so an empty or
  data-losing server never wipes the phone ("Upload this phone's data"
  restores a server that lost its database).
- **Switch ops carry when they were made.** An offline switch that reaches
  the server after a Shortcut switch ends where the Shortcut's segment
  starts, instead of erasing it (shared `switchCategory` `madeAt`). Switch
  rows are stamped with the op's `createdAt`, so a later Undo or edit wins.
- **Free-plan limits shaped the server**: at most 15 ops and 200 segment rows
  per `/api/ops` request; segment upserts use prepared statements, not
  Drizzle (CPU); snapshot paged 500 segments per page; overlap queries use
  `segments_ended` and never walk history; at most 3 push sends per cron
  run; CSV export formats times with one Intl lookup per day.
- **One-open-segment index** is `ON segments((ended_at IS NULL)) WHERE ended_at
  IS NULL AND deleted_at IS NULL`. The original `ON segments(ended_at)` enforced
  nothing because SQLite treats NULLs as distinct.
- `POST /api/switch` refuses an `at` more than 24 hours back.
- Export is built on the phone from IndexedDB; the app never calls the
  export endpoints.
- Palette: 16 colours validated for contrast in both themes
  (`packages/shared/src/seed.ts`). Casual work uses a concierge bell icon.

## Known limitations and follow-ups

None blocks use. Each is documented where it lives.

- **Clock skew**: if the phone's clock is behind the server's, an edit made
  within that skew after a Shortcut write loses last-write-wins and is
  reverted. Fix idea: stamp `max(now, previous updatedAt + 1 ms)` in shared
  `Working.result()` (tests assert `updatedAt === now` and would need
  updating).
- **Refused chunk during "Upload this phone's data"** on a partly restored
  server triggers a full resync that can drop up to 100 local segments the
  server never got. Fix idea: suppress the full resync while an upload is
  draining.
- **Push health check**: turning notifications off while a launch check is
  mid-flight can re-register; if the server lost its subscription rows but
  keys are unchanged, the background check reports ok (Settings notices).
- **Concurrent requests**: each op reads in one batch and writes in another,
  so a Shortcut switch racing an outbox edit could in theory leave an overlap
  (two open segments are still caught by the index).
- `GET /api/export.json` is not paged; only manual use, the app does not
  call it.
- Stats: a full-year custom range takes about 1.5 s at 4x CPU throttle (fine
  unthrottled).
- Not built: the optional read-only `WIDGET_TOKEN`; the widget uses the app
  token.
- GitHub Actions are pinned by tag, not commit SHA.

## How to continue the work

- Branch and PR flow used: develop on a branch, one PR per milestone or
  change, merge with a merge commit after CI is green.
- Checks before any push, from the repo root:
  `pnpm lint && pnpm typecheck && pnpm test && pnpm build`.
- Server tests run the real Worker in workerd with an in-memory D1 through
  wrangler's `createTestHarness` (`apps/server/test/harness.ts`).
  `@cloudflare/vitest-pool-workers` was rejected: its pinned workerd does not
  support the project's `compatibility_date`.
- Client sync tests use `apps/web/src/sync/testServer.ts`, a fake that models
  the real server (15-op cap, last-write-wins, 10 s overlap, paging).
- End-to-end checks of the built app: [tools/e2e/README.md](tools/e2e/README.md).
  Run `tools/e2e/sync` (16 checks against the real Worker) after any sync
  change.

## Lessons from this session (avoid repeating them)

- **Never `pkill -f <pattern>`** when the pattern also appears in the shell
  command running it: it kills its own shell. Stop servers by port or by a
  PID list that excludes `$$`.
- **Leftover preview servers** keep their port and serve an old build. Use
  `--strictPort` and check which process owns the port.
- `pnpm lint | tail` hides lint's exit code; test the exit status, not the
  tail.
- A fresh git worktree needs `pnpm install` before lint, typecheck or tests.
- D1: a statement takes at most 100 bound parameters (use the `json_each`
  `idIn` helper for id lists); budget 50 D1 calls per invocation; Workers
  Free gives 10 ms of CPU per invocation.
- `wrangler dev`: trigger the cron with
  `curl "http://localhost:<port>/cdn-cgi/handler/scheduled?cron=*+*+*+*+*"`.
  A fetch to a host that does not resolve logs an "Uncaught internal error"
  from workerd itself; real push hosts resolve.
- `wrangler deploy --secrets-file` uploads secrets with the version;
  `wrangler d1 create --no-update-config` keeps CI from editing the config.
